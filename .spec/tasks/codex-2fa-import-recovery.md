# Codex 2FA JSON 导入与 401 停调度后恢复

目标：在当前 sub2api 内完成导入、账号配置和恢复；team-manage-refresh 仅作为研究参考。禁止 CPA 推送。用户授权只用原始文件第一个账号实测。

1. 登录适配器：复用已实测的独立 Python/Node HTTP 登录进程，以本项目内部 worker 提供接口；Team 优先，仅无 Team 时用个人；恢复绑定原 workspace；日志与进程参数不得包含登录材料。
2. 后端：独立私有表加密保存材料与持久化任务；导入后按现有 AdminService 创建账号配置；401 先停止调度，再从独立队列重新登录；新凭据通过验证、缓存失效后恢复同一账号。失败保留停用，有限重试、跨进程互斥。复用现有 proxy/IP 组。
3. 前端：账号配置页独立 2FA JSON 导入入口，支持多个文件、任务状态、逐项失败原因、手工重试；不改变原 Token JSON 导入。
4. 验证：解析/授权优先级/身份约束、队列与 401 恢复、保留账号配置、失败保持停用、前后端构建和界面 HTTP 验证；记录实际 live 与 mock 边界。

执行顺序：1 → 2 → 3 → 4。完成后回写 journal 与功能知识导航。

## 交付证据

交付目标为 origin/main-kin。沿用目标分支的分模块语言文件、Wire 依赖及默认并发 8，没有合入 dev 的其他功能。

目标分支验证：相关 Go 单元回归、独立 PostgreSQL 的任务租约与原子恢复、集成标签 go vet、前端 11 项测试、typecheck/build 与开发页面 HTTP 200、Python 8 项测试通过。第一个真实账号的最终 Worker HTTP 登录与额度验证成功，凭据在目标分支解析校验通过；其余四个账号未登录。
