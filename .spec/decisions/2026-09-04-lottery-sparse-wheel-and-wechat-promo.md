# 抽奖转盘稀疏化与公众号引导

- 状态: 生效

## 背景

奖品数进入转盘格子后，100 个奖会画出 100+ 格。同时需要引导关注微信公众号，并在中奖站内信里带同一套广告图。

## 决策

1. **转盘视觉固定 8 格**（奖品 / 谢谢参与），与 `prize_count` 脱钩。开奖在「剩余奖 ≥ 剩余名额」时必中；名额多于奖时才按相位加权概率抽。
2. **一套素材三处共用**：引导文案 + 一张图，用于抽奖前（可跳过）、中奖结果、中奖站内信。未中不展示、不另发信。
3. **图片只接受公开 HTTPS（方式 A）**，对象放在现有备份 S3 / R2 桶（建议 `lottery/` 前缀）。管理端粘贴公开域名下的直链，例如 `https://pub-xxxx.r2.dev/lottery/wechat-qr.png`。
4. **不把备份下载预签名 URL 当图片**。备份链路带 `Content-Disposition: attachment`，浏览器会下载而不是渲染。也不在活动或站内信里存 data URI。
5. **本期不做管理端选文件自动 PutObject**。备份 S3 配置没有 `public_base_url`，自动上传无法稳定得到可给 `<img>` 用的永久链接。

## 替代方案（未采用）

- 转盘格子数 = 奖品数：已导致 100 奖视觉过密。
- data URI 上传：弹窗可用，但复制进每封中奖站内信会胀库。
- 复用备份 PresignGetObject：强制附件下载，不能扫码。
- 微信关注真校验：超出范围，也做不到稳定验证。
