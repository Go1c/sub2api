# 探测代理池与 Turn-State 业务注入

## 目标与边界

探测轨按图中三步跑：廉价动态 **IP**（图中为 IPv6）→ 轻量探针捕获 `X-Codex-Turn-State` → 长度或题目过滤。**每个账号当前只有一张 state**。业务轨：日常请求走账号原 IP 配置，网关中间件强制注入或替换这一张票。

**探测出口、题目、模型、复查间隔全部放在渠道管理子页**，不在 IP 管理再开「探测代理池」。账号编辑只留开关。每 20 分钟续采；刷新中或采集失败保留未过期旧票，成功后替换。答对一次即可挂上。

日常流量完全沿用账号原本的代理 / IP 组选路。新对话并发先从状态为「已挂票」的账号里抢槽，同批挂票再按账号优先级；挂票账号没空位才回落到其余账号。粘性会话若当前账号已挂票则继续钉住；未挂票则先找可抢的已挂票账号并改绑，找不到才留在原账号。必须打在目标模型上；`gpt-6-astra` 被改成 `gpt-5.6-luna` 废本趟、换 IP。图里的 ping 是短 Responses。完整 state 不进管理页。注入在跨凭证守卫之前。

非 OpenAI OAuth、认不出轮次则跳过注入。关闭账号开关或渠道策略后，停止新采集和新轮注入。

| 现有资产 | 接入方式 |

## 管理界面

配置和开关拆开：渠道管策略，账号只管开不开。

### 渠道管理：新增子页

`/admin/channels/turn-state`。探测出口和策略都在这一页，IP 管理不新增入口。

| 字段 | 默认 |
| --- | --- |
| 探测出口 | 勾选已有代理，和/或填写动态代理（主机、账号模板、`sid` 轮换）。日常选路不用这些出口 |
| 目标模型 | `gpt-6-astra` |
| 长度过滤 | 开，最低 160 |
| 测试题 / 标准答案 | 摸糖果题 / `21` |
| 模糊匹配 | 开 |
| 续采间隔 | 固定 20 分钟；读取旧配置时统一为 20 |
| 连续 overloaded 触发次数 | 默认 3，范围 0–20；0 关闭该触发 |
| 每分钟调用预算 | 6 |

立即探测、暂停、按账号查看当前票也在这个子页。策略 revision 变了，已挂的 state 要按新策略复查或重采。

住宅 IP 和 IP 组仍只在 IP 管理里，给账号日常流量用。

### 账号：仅一个开关

仅 OpenAI OAuth。开：用渠道策略采票并在日常请求替换 state。关：立刻停新采和新轮注入。

`accounts.extra.turn_state_probe` 只存 `{ "enabled": true|false }`。存量缺省 = 关。新建 / JSON 导入 Codex 默认开。

## 探测、复查与换新

1. 探测 IP 池只换出口，最多 10 个账号并行。每次调度只采一次，普通暂时失败或调用预算耗尽后 45 秒再试，仍受全局与账号 RPM 预算约束。未分类的 HTTP 403 按 2、4、8、16、30 分钟退避，随后保持 30 分钟；403 次数跨 RPM 延迟保留，成功采票后归零。下一次采集重新生成动态 sid。401、无 token、非活跃账号，以及 403 正文中明确的凭据失效 / 账号或工作区停用错误停止自动采集并清票，可手动重新探测。
2. 短 Responses 从 HTTP 响应头取 `x-codex-turn-state`。不发 `max_output_tokens`，使用渠道目标模型；题错、模型改写、无 state、长度不够均不替换当前票。
3. 每个账号一张当前 state。记录 `harvested_at` 与 `expires_at`，按采集请求开始后 1 小时管理本地有效期；这是基于使用反馈的有效期假设，不是上游保证。Redis 记录的保留时间不等于上游票据有效期。
4. 20 分钟续采一次，刷新中与失败重试期间仍可注入未过期旧票；未知 403 同样保留旧票，重试不延长旧票有效期。过期即停止使用。旧 `holding` 记录用成功采集的 `updated_at` 推导有效期；旧 `running` 记录无法确定采集时间，不继续使用。
5. 复用账号请求健康记录，按发生时间合并同账号各出口，最近连续 N 条为明确 overloaded 才触发续采；成功或其他报错打断连续计数。新票采集之前的旧错误不重复触发。正在刷新/重试的账号合并重复通知。触发后下一次 runner 轮询（约 1 秒）采集，实际受日志处理、并发槽位和调用预算约束。
6. 策略或账号开关关闭时不触发；后台可配置 overloaded 阈值（默认 3，0 关闭，最大 20，对应现有健康历史容量）。管理员设置读回带 `overload_threshold`。日志仅含账号、哈希、长度和错误原因，不记录 state 原文。

### 403 恢复与诊断

Pro 与 Team 继续共用 HTTP 响应头采票，不按账号名称、套餐或成功票长度切换协议。未知 403 进入 `cooldown`，不永久停采；明确的账号级拒绝使用独立错误码 `TURN_STATE_PROBE_ACCOUNT_FORBIDDEN` 并进入 `skipped`。存量 `skipped` 中仅旧 `TURN_STATE_PROBE_FORBIDDEN` 可在最后记录两分钟后重新进入自动调度；401 和其他原因不自动恢复，之前已清掉的旧票无法找回。

403 正文最多读取 16 KiB + 1 字节，仅完整 JSON 的结构化认证 / 账号状态错误作为停采依据，HTML、自由文本和不完整响应不能据此停号。日志记录账号 ID、固定枚举的 Content-Type / 正文格式 / 错误分类、正文是否完整、经过长度和字符检查的请求 ID / CF-Ray、CF challenge 标志，以及 state 长度与哈希。响应原文、error.message、凭据、代理地址及完整 state 均不记录；诊断分类不能单独证明 403 来自代理或 WAF。

## 业务注入

新对话选路时优先已挂票账号的空闲并发，没有空位再走无票账号。粘性会话已挂票则继续钉住；未挂票则改绑到能抢到槽的已挂票账号，否则保持原粘性。有当前 state 则强制替换出站 `X-Codex-Turn-State`。HTTP 写请求头；WS 写帧内 `client_metadata`。会话绑定按票据哈希分代，绑定 TTL 不超过票的剩余寿命；续采成功后，同会话后续请求也改用新票，旧的 2 小时绑定不再读取。还没有票时不注入、原样转发，不 503。

## 数据与接口

渠道一份策略（含探测出口与题目等，带 revision）。账号 extra 只有开关。Redis 存账号当前 state、采集/过期时间、下次续采或重试时间、租约、预算、会话分代绑定。

| 接口 | 行为 |
| --- | --- |
| `GET/PUT /admin/channels/turn-state-probe` | 渠道子页：探测出口 + 策略 |
| `GET /admin/channels/turn-state-probe/accounts` | 已开开关的账号及票摘要 |
| `POST /admin/accounts/:id/turn-state-probe/enabled` | 只改开关 |
| `POST /admin/accounts/:id/turn-state-probe/run` | 立即探测 |
| `DELETE /admin/accounts/:id/turn-state-probe` | 清空该账号当前票 |

现有业务 API 请求格式不变。

## 验收

- 账号页不能改题目、间隔、探测出口，只能开关。
- 探测出口只出现在渠道子页，不在 IP 管理增加菜单。
- 渠道子页改策略后走新 revision。
- 答对一次挂票；Astra 变 Luna 废本趟；日常仍走原业务出口。新对话并发先从已挂票账号里找。粘性未挂票则改绑到能抢到的已挂票账号，找不到或粘性本身已挂票则钉原账号。

跨 IP 接受程度未做上游实测：代码按账号共享票，不能据此保证跨 IP 使用不会被拒或降级。

回退：关账号开关或关渠道策略。不删表、不拆业务流。
